# GDA-007: File Locking for Concurrent Operations

**Status:** Open (v2 feature)
**Priority:** Low (single-user tool for now)

## Problem

`gda gc` and `gda add` can race: if a user runs `gda add` concurrently with `gda gc`, the GC could delete an object that a concurrent add just created but hasn't yet indexed.

Current mitigation: 1-hour grace period on GC (objects younger than 1 hour are not deleted).

## Expected Behavior

A cross-process lockfile (`.gda/lock`) prevents concurrent mutating operations. Use `flock` syscall via Go's `golang.org/x/sys/unix` or a simple PID-based lockfile.

## Non-Goals

- Read operations (`status`, `log`, `whereis`) don't need the lock.
- Concurrent reads while a write holds the lock are fine.
