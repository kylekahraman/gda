# GDA-005: Store.Add Reads New Files Twice

**Status:** Open (optimization)
**Priority:** Low

## Problem

The current dedup fix in `Store.Add` reads the entire file to compute the hash, then if the object doesn't exist, opens and copies the file again. For new multi-GB files, this doubles I/O time.

## Root Cause

AGY's fix added a separate hashing pass before the copy. The original MultiWriter approach (hash + copy simultaneously) was better for new files but couldn't check for duplicates beforehand.

## Potential Solutions

1. **Write-then-check:** Write to temp via MultiWriter (hash + copy), then check if the key already exists. If yes, delete temp. If no, rename. One read for new files, one write for duplicates.

2. **Skip check entirely:** For prototype, accept that re-adding the same content rewrites the object. GC will clean up duplicates.

## Recommendation

Implement solution 1 (write-then-check) before dogfooding on real TB-scale data.
