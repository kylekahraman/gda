# GDA-002: Move Deletes Non-Symlink Source Silently

**Status:** Fixed
**Fix details:** `gda mv` now checks `os.Lstat` before proceeding. If the source is not a symlink, it aborts with a message instructing the user to run `gda add` first.

## Problem

If a user replaced a tracked file's symlink with a regular file (e.g., an editor wrote through the link permissions, or the file was replaced manually), `gda mv src dst` would:
1. Read the old key from the index
2. Create a new symlink at `dst` pointing to old content
3. Call `os.Remove(srcAbs)` — **deleting the user's modified content**

The user's changes were silently lost.

## Reproduction

```
gda add file.txt
# User edits file (writes through symlink)
gda mv file.txt subdir/file.txt  # user's edits are gone
```

## Fix

Before moving, check:
1. `os.Lstat(srcAbs)` — verify it's a symlink (`fi.Mode()&os.ModeSymlink != 0`)
2. If not a symlink → error: "safety abort: file is not a symlink. Run 'gda add' first"
