# GDA-003: Index Writes Not Atomic

**Status:** Fixed
**Fix details:** `Index.Save` now writes to `index.json.tmp`, calls `f.Sync()`, then atomically renames via `os.Rename`.

## Problem

`Index.Save` used `os.WriteFile` which truncates the file before writing. If the process crashed (Ctrl+C, OOM killer, power failure) during the write, `index.json` would be left corrupted or empty. The entire tracking state would be lost.

## Fix

Atomic write pattern:
1. Marshal JSON to `index.json.tmp`
2. `f.Sync()` to ensure data is on disk
3. `f.Close()`
4. `os.Rename(tmpPath, idx.path)` — atomic under POSIX

The repository always has either the old valid index or the new valid index.
