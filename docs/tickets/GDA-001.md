# GDA-001: GC Deletes Snapshot-Referenced Objects

**Status:** Fixed
**Fix details:** GC now traverses all snapshot files and includes their keys in the reference map before removing objects.

## Problem

`gda gc` only checked the current index when determining which objects to keep. Any object referenced in a past snapshot but not in the current index was permanently deleted. Checking out a past snapshot would result in broken symlinks.

## Reproduction

```
gda add file.txt
gda snapshot snap1
# ... modify and re-add file.txt ...
gda gc  # deletes the original object referenced by snap1
gda checkout snap1  # broken symlink — object missing
```

## Fix

1. After collecting referenced keys from the current index, also load all snapshot manifests and add their keys to the reference map.
2. Added a 1-hour grace period on object mtime to protect objects created by concurrent `gda add` operations.
